## Native representation and player entry

Each logical tradition has one owned native NameCulture and five exact-gender RandomNameProfiles (75 native rows): Male uses male+shared; Female female+shared; Indeterminate, Neuter and NonBinary use the union. An empty gender subset falls back to shared then union. Every eligible exact form has weight1. The new culture opt-in disables the engine's legacy wildcard matching for these profiles in both chargen and NPC generation. Existing worlds retain their legacy policy. Case, curly apostrophes and Unicode hyphens remain exact; all supplied strings are NFC, BMP and at most13 characters, within current schema capacity.

Only personal name is an executable native element and random dice expression (`1`). All78 descriptions, defaults and constrained components are retained in each applicable culture's `CuratedNamingDefinition`, which survives runtime save/clone. Family affiliation cannot be verified by this generic name picker; tribe/clan membership and completed-apprenticeship path eligibility also lack native naming slots. These supplementary definitions therefore remain curated background data, disabled in generic random generation. No tribe is stored as a surname, clan as a middle name or earned path as an adult name. Their full descriptions, exact parent-clan map, optionality, unlimited alias cardinality, path-prefix rule and explicit display flags remain in the manifest/curated definitions for a later eligible background UI. The installer does not infer membership, rank or eligibility from choosing a name.

Upbringing naming is the default. Owned ethnicity overrides are absent, so a City Elf does not silently get Labyrinth upbringing or a forced racial naming convention. A configurable NamePicker style prog offers the selected upbringing and matching racial tradition; `/style <number>` optionally changes only the personal-name convention. Half-Elf/Half-Giant traditions remain independently selectable definitions using the Human pool. Free entry remains available for every gender. Completion uses the selected name culture, and existing personal-name XML preserves it across resume. Compatible pre-existing naming-style delegates are composed; later builder pointers and Unicode choices are reconciled, not overwritten. The old `arm.naming.personal` identity remains valid for older character/name references.
