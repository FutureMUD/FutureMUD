# Fury stamina removal correction

Independent review of source checkpoint `a53f1d15e6a1195d0ba28c075816894605cbad84` found that native `EffectHandler.RemoveEffect` invokes `RemovalEffect` before removing the child from the owner's effect list. Recomputing capacity during that callback still counted the departing Fury, even though its parent ownership link had already been removed. The previous XML and calculation tests did not exercise this lifecycle.

`SpellSourceFuryEffect` now marks only itself as departing before parent-link cleanup and capacity reconciliation. Its trait applicability returns false during removal. The existing world maximum-stamina prog therefore excludes this bonus while retaining every other applicable Fury bonus. Initial attachment/login restores trait applicability before reconciliation. The body still uses its existing capacity prog and current-stamina clamp; this correction does not call `InitialiseStamina`, fill stamina, or reset exertion or heartbeat state.

`EmotionalStaminaLifecycleTests` uses the actual native `EffectHandler`, `EffectScheduler`, `MagicSpellParent`, registered dispel adapter, `Body.TraitValue` and body stamina setters. Its explicit fixture attribute has raw value10 and a fixture capacity prog `100 + effective attribute * 10`. This is a test configuration, not an authored stock default. Each expiry/dispel case proves attachment without refill, parent/child removal, capacity/current clamp, unchanged exertion and heartbeat flags. Two additional variants retain a separately cast Fury and its scheduled parent.

The complete pre-fix fixture reproduced four failures: expected baseline capacity200 versus stale240, or expected retained capacity220 versus stale260. The first two fixture attempts failed compilation (incorrect exertion namespace and inaccessible adapter constructor); a third attempt proved expiry failure while revealing an incomplete mocked dispel predicate query. These diagnostics are preserved locally. The final corrected fixture reproduces both real expiry and real dispel paths before the production fix, and the focused corrected run passes37 cases with no failures/skips. The separate final receipt binds broader execution to the committed source and executed assemblies.

This bounded runtime regression uses mocked world/character dependencies and an explicit fixture capacity prog. It does not qualify a seeded world's compiled prog, database boot/reload, paid Fury/Calm casting, combat authority, selective Calm cessation, or stock construction. The endurance mapping and Calm attack-break choices remain pending. No main-owned method, Pierce factory/contribution, central ledger, or shared harness dispatch changes in this correction.
