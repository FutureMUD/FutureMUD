### Exact current prerequisite

`DetectInvisibleEffect` in `MudSharpCore/Magic/SpellEffects/StandaloneStatusSpellEffects.cs` inherits only `CharacterSpellEffectTemplateBase`. It returns a persistent native child, but does not implement `IMagicSpellEffectOperation`. In `MagicSpell.cs`, the configured path sets `AppliedIntendedOperation` only from an operation report with status Applied; the legacy child-returning branch does not set that flag. `MagicCastingService.Execution.cs` stores that flag in the operation payload and requires it for successful-operation mastery credit. A paid cast can thus create detection while reporting no intended application for advancement.

The minimal prerequisite is to make only this concrete adapter partial and implement the existing operation-reporting interface in a dedicated file, following the already reviewed `DetectMagickEffect.Operation.cs`: reject a non-character, create the existing native child once, and report Applied only when that child exists. Do not change the shared base, other statuses, `MagicSpell`, the casting/payment pipeline or the interface. This is a bounded adapter completion, not a framework expansion. The current continuation request specifically asks for content supported by already reviewed adapters; return this prerequisite for coordinator scope selection before broader implementation.
