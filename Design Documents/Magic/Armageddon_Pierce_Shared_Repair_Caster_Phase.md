# Exclusive cleanup compatibility for primary and caster phases

The initial shared repair `df77d09c` invokes the existing cleanup action when exclusive parents are replaced. A bounded additional control exposed a same-cast compatibility case in that exact owned method: `MagicSpell.CastSpellCore` invokes local `ApplySpellEffect.FinaliseParent` for both primary and caster effects. When a spell targets its own caster, the second finalisation selected and removed the primary parent created by the first. The diagnostic expected two bound parents but observed one; its failure remains in `.artifacts/test-runs/pierce-shared-self-caster-01`.

`CastSpellCore` now keeps a local reference-identity set of parents attached by the current cast. Exclusive replacement still removes prior-cast parents and runs existing child cleanup, but excludes these new parents from later phases of the same cast. This is limited to the existing finaliser; it adds no interface, schema, payment or global-removal change. `ResolvePreparedSpell` already performs its target replacement before adding its target and caster heads; its authorized explicit cleanup remains unchanged.

The regression uses the actual detection templates and configured paid casting service. Dedicated native controls author a separate unowned fixture spell with both primary and caster detection effects, admit it through the existing capability builder and staff `Grant`, then perform ordinary paid casts. They verify both new parent/child pairs survive, both prior pairs and schedules are removed on recast, ordinary expiry removes both, and an independent process restores and expires both without removing the separately saved Pierce parent or changing reserves. The normal stock definition is not modified by this fixture.

The earlier full packet on `df77d09c` passed 7,436 units and all selected native modes but did not contain this compatibility control. It remains historical evidence, not final qualification of this subsequent source. A new exact-source packet is required after the compatibility commit.

Pierce stock remains content-blocked on the separately documented accumulated cap48/retained maximum power policy. This guard preserves newly created parents; it does not implement historical accumulation or make replacement refresh source-equivalent. See `Armageddon_Pierce_Shared_Repair_Integration.md` for the verified `RT_ZAL_HOUR600` clock conversion and bounded lifetime-policy dependency. Central ledgers, installer, stock factory, historical receipts and shared native dispatch remain unchanged.
