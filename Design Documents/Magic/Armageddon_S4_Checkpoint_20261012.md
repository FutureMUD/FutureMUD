## Read Attunement adapter

`readattunement` is an ordinary character-target spell effect. The selected subject carries a native description addition under its normal spell parent. Only the exact canonical caster and physical casting instance can read it, while that instance can still see the subject. The normal casting pipeline resolves that subject's eligibility, wards and resistance before attaching the effect; no ambient reading of unrelated subjects is introduced. The parent owns scheduling, saving, expiry and removal. The `readattunement` dispel key selects only this effect.

Output has two distinct facts: assigned elemental affinities come only from `IElementalAffinityMerit`; learned magical affiliations come from exact completed durable capability enrolments. Completed enrolment follows the successful durable starting acquisitions. A canonical spell acquired elsewhere, raw skill, species/name or temporary capability cannot identify a teaching route. Pending, wrong-owner, wrong-capability or wrong-identity enrolments are not reported as complete. Current active/inactive permission checks the viewed physical body's attached capability and enabled valid policy. A temporary attachment can reactivate an already learned route but cannot create history; this matches ordinary casting permission. Inactive history survives loss of permission and restart. Reserve balance, hands or casting lockout do not erase learning history.

The query never enrols, grants, trains, rolls, refills or saves. A failed durable read displays `Unavailable`, separately from `None`, without exposing provider diagnostics. The saved child uses declared `CasterId`/`CasterInstanceId` fields; no arbitrary numeric text is inspected.

Nine adapter regressions are included in a passing 70-test focused Core gate, covering exact enrolment, shared-spell noninference, inactive history/restart, canonical ownership across bodies, explicit affinity separation, visibility/exact-caster disclosure, failed durable reads, template/child/parent reload, paid ordinary pipeline application, parent removal, zero-payment refusal and live/nested typed physical references. The pipeline test uses the established bounded casting fixture; it is not a paid installed-stock acceptance test. A separate 37-test room-reference gate passes with direct/nested child payload byte preservation. Explicit effect inventory entries preserve completeness coverage and refuse unqualified frozen carriers. Initial compile failures exposed the prog-specific LOOK interface and two test API/type assumptions; corrected attempts and logs remain under `.artifacts/s4-attunement-focused*`.
