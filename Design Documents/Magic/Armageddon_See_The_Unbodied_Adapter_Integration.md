# See the Unbodied: allocated ethereal adapter checkpoint

This checkpoint implements the coordinator's allocated operation reporting and typed cumulative lifetime support. It prepares the source duration contract; it does **not** provide an installable See the Unbodied stock factory or conditional Divination component selection. The separate [exact-file proposal](Armageddon_See_The_Unbodied_Component_Proposal.md) needs coordinator allocation before that selection implementation. Its proposed route uses existing prepared-selection and payment APIs without shared payment/selection edits.

`DetectEtherealEffect` now implements the configured effect-operation interface in its own partial. It owns attachment and reports the observed retained child, rather than returning a merely allocated child for the caller to attach again. Invalid recipient/parent ownership refuses. Retained attachment reports Applied; repeat application to an already attached child reports NoChange; unrelated mutation or incomplete ownership reports Unknown. Attachment exceptions retain only proven child ownership so the existing casting exception path can schedule a bounded parent and quarantine paid uncertainty. Legacy `GetOrApplyEffect` still returns an unattached child.

The effect has an optional editable lifetime policy using the existing version1 accumulate XML schema and parser. `effect N lifetime accumulate <group> <seconds per unit> <maximum units>` and `lifetime off` use normal builders. Clone/save/reload preserves valid policy and preserves invalid policy bytes while failing closed. A source-authored See policy is group `armageddon.detect_ethereal`, 600 seconds per historical hour, maximum36 units, expression `1800*grade` and exclusive replacement. Existing absent-policy definitions retain ordinary spell durations.

The specifically allocated bridge changes are the one class declaration in `StandaloneStatusSpellEffects.cs` and typed admission in `MagicSpell.Lifetime.cs`. Invisible, ethereal and scoped-water cohorts remain distinct concrete child kinds even when a builder reuses a group string. New replacement children are checked too. The bridge retains existing immutable membership/deadline confirmation, whole-unit accumulation, cap, strongest source grade and associated editable power, scheduler, persistence and callback/cleanup rules. No new lifetime implementation or status-base generalization is introduced.
