# See the Unbodied: separate source-component adapter checkpoint

This implements the coordinator's subsequently allocated component adapter using the existing prepared-selection, casting journal, native inventory plan and ethereal lifetime APIs. It follows the source qualification and exact-hook proposal already committed in this lane. The earlier adapter receipts and proposal remain historical records. This checkpoint does not qualify a source stock factory, acquisition prerequisites, minimum Standing, practice, installer integration or charged carriers.

The optional `detectethereal` XML adds `<SourceScope version="1" silt="ID" shadow="ID" component="unique.reference"/>`. Both terrain IDs must exist in the native catalogue. The actual caster cell's current overlay terrain determines the branch. Silt refuses first, including deliberately overlapping Silt/Shadow mappings. Shadow omits only the precisely referenced Divination consume action; all other authored actions remain. Outside Shadow every grade consumes one directly carried quantity unit with rank `max(grade-3,0)`. Rank tags0-4 must form a native ancestor hierarchy beneath the action's family tag. Higher descendants qualify. One quantity unit is the declared adaptation of historical whole-object extraction.

Ordinary authoring uses the existing spell builders: add a self trigger and `detectethereal`; configure `lifetime accumulate armageddon.detect_ethereal 600 36`, exclusive replacement and `1800*grade`; then `plan add consume <Divination family/rank0 tag> 1`, `plan carried 1 on`, and `plan ranks 1 -3 <rank0> <rank1> <rank2> <rank3> <rank4>`. The owned effect builder adds `effect 1 source component <action number> <unique reference>` and `effect 1 source <Silt terrain> <Shadow terrain> <matching reference>`. Action numbers flatten native phases in order. `source off` restores ordinary ethereal detection. Reference editing replaces only the chosen native consume action, retaining its delegates, phase order, options and unrelated action objects. Invalid source XML is preserved and fails closed. Clone/save/database reload retains the scope.

The immutable token freezes the original canonical spell/plan configuration, action types and runtime delegates, selected grade, body/cell/overlay/layer, terrain definitions and branch, component identity/prototype/stack/quantity/custody, and relevant tag ancestry. The token is frozen before native rank binding as well as planning callbacks. Native planning resolves the component without executing the plan. Capture reconfirms the original token after CreatePlan, feasibility and Peek callbacks. It inspects cached native scout inputs rather than rescouting. A second authored action or native hand-clear receipt sharing the selected component refuses before payment. Native actions whose inputs are omitted from Peek/payment receipts are explicitly unsupported; ConsumeCommodity is an example. Existing accumulated-lifetime readiness requires a sole supported effect and already refuses competing multiple source-scoped detection effects before payment; the adapter uses that existing rule. Custom templates/actions and runtime fitness scorers that native XML casting copies cannot preserve are also explicitly refused. Supported primary and secondary selectors are retained.

Fresh invocation copies reuse the same token and selected item; they never choose a new environment branch or replacement. The composed dedicated selector runs preserved selectors and rank checks first, then raw frozen configuration/environment/custody/quantity/ancestry checks. Native `RevalidateConsumption` calls that selector after debit. A private invocation-local template wrapper delegates execution to the existing native plan, records attempted phases, then verifies actual quantity decrease or genuine whole-item disappearance. A returned Consumed result alone cannot authorize perception. Ambiguous refills, failed deletion, replacement, custody drift or configuration/environment drift quarantine through the existing NeedsReview journal before new perception or mastery. The effect operation reconfirms the observation after native finalisation; source-scoped legacy factory calls also require that observation. Absent source scope preserves the previously cleared generic adapter.

The dedicated EtherealComponentAdapterNativeHarness links existing helpers and regression partials read-only. Its entrypoint and runner are separate from shared dispatch. Each run creates an exact-identity guarded loopback MySQL instance under `futuremud-ethereal-component-adapter-mysql_<UUID>`, lane-owned output paths and a fresh ownership-marked database. Concrete native Character, Body, GameItem, Stackable, Tag, SimpleMagicResource, inventory consumption, scheduler, spell/effect persistence and fresh readers verify the adapter. Cell/terrain catalogue mappings, anatomy/race and successful casting checks remain explicit fixture mocks. This is not a production world boot or historical Silt/Shadow topology verification.
