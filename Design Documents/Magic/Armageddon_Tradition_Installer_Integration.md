# Armageddon partial source-tradition installer

This is a bounded, programmatic content checkpoint on the charged-device branch. It is not an enabled interactive seeder or a complete Armageddon preset. It adds durable native skill, capability and merit definitions without installing missing spell payloads, attaching player merits, enrolling actors, refilling mana, refreshing player state, creating classes or changing existing casting/payment authority. Optional classes are deferred until the traditions have usable complete repertoires.

## Authority and source traceability

The authoritative `Armageddon_Magic_Completion_Implementation_Brief.md` was read through the supported Library flow, Library ID `libfile_a4606cd0097081918d6c9d9e220e6da0`. All 94 committed rows in `Armageddon_Sorcerer_Source_Tree.json` were compared with Appendix A field for field: order, kind, historical and normalized names, parent, parent threshold, opening, raw cap, branches-at and printed minimum mana. No discrepancy was found. The JSON is embedded as `ArmageddonSorcererSourceTree`; the original file and central progress ledgers are unchanged.

The 82 distinct Sorcerer spell skills are shared across general Sorcerer, Preserver and Defiler variants. The four source roots open at 60; other spells open at 30. Caps are 90 except Mend Flesh at 60. A child's threshold comes from its source parent's branches-at value. The Shadow Passage → Component Crafting → Identify bridge stays typed support/skill content; it is not converted into a dummy spell. Source raw-skill thresholds and cap-relative controlled-grade gates remain different native mechanisms.

## Installed content and explicit dependencies

`ArmageddonTraditionInstaller.Install` takes an explicit `ArmageddonTraditionInstallPlan` in a fresh dedicated database context. The caller selects existing school, player-capable source and reserve resources, native decorator, compiled no-argument true/false progs, validated skill-level gathering template, reviewed implemented spell bindings, and native support counterparts. No resource capacity, attribute mapping or gathering economy is invented. Resource definitions and their builder-owned capacity progs/expressions remain external dependencies.

The module `partial-source-traditions`, version `partial-1`, owns 171 records: one classic use improver, 82 skill-cap expressions, 82 character-owned native spell skills, three skill-level capabilities and three actual Magic Capability merits. Skills have ordinary builder-editable cap expressions and use improvement; they do not use branching-improver grants to bypass typed acquisition. The default improvement chance, gain and cooldown are editable package tuning, not historical source facts.

The implementation takes the prerequisite closure of supplied real spell definitions and the explicitly selected Gather, Component Crafting and Vloran counterparts. Current reviewed utility bindings expose Sense Enchantment and Unravel Enchantment roots, plus Draw Water at Unravel 80: three admissions, with the other 79 source spells explicitly unavailable. Mend Flesh and Hover Body definitions do not bypass their unavailable parents. All 82 skill definitions exist, but skill existence never grants spell knowledge or a controlled grade.

Gather is required as a real character-owned skill with a native cap/use improver; it supplies concentration and enrolled gathering support (source opening 10, cap 90). Component Crafting additionally needs an existing approved native craft using the selected skill. Vloran needs an existing native language linked to its selected skill. The other support rows remain traceable source data and explicit counterpart mappings; unrelated mundane and psionic roots receive no automatic grants. Missing support branches stay unavailable. The installer does not edit the external skills, caps, crafts, languages or template.

## Gathering and entitlement policy

The brief's Mana Capacity and Regeneration section explicitly calls the following matrix an engineering proposal. Defaults select Self/Gentle/Land for general Sorcerer, Self/Gentle for Preserver, and Self/Land for Defiler. This is an editable policy selection; it does not add imagined source exclusions. `AllowedMethods` can explicitly replace each variant's selection, including a bounded available subset. Missing selected method kinds block installation.

Native methods are copied with their complete prices, progs, source selectors, ecological policy, emotes and numerical settings. Only stable method/source identities are remapped per variant. Preflight uses the native gathering loader and validator in a disposable offline world, with selected read-model resources and compiled policy signatures. No policy prog is executed. Malformed selectors, optional collateral, missing ambient resources, free Self policies, missing Land scar costs and incompatible policy progs are rejected before writes. This verifies configuration; it does not certify every configured price's gameplay balance.

Every installed capability has an explicit source/reserve map, individual spell proficiency trait, source opening/cap, typed prerequisite and cap-relative grade interpretation. Passive regeneration is disabled and the copied regenerator list is empty. Its real capability merit is unavailable to chargen by default. A builder-owned admissions path must attach the appropriate merit and explicitly call the existing `enrolchannelcasting(actor, capability, provenance)` hook. Loading the world, installing or rerunning this module, and merely acquiring a skill perform no enrolment. Enrolment does not fill reserves; reruns do not apply new openings or re-award player state.

## Durable ownership and reruns

All records and content commit together in one serializable native transaction. Stable module keys, retained logical IDs and per-field three-way baselines preserve builder renames, cap/formula edits and capability policy edits. Clones are unowned. Missing, retired or multiply claimed owned identities and unowned name collisions block the whole batch; no automatic adoption or resurrection occurs. Unknown module keys require explicit version reconciliation. Dependencies and source rows are recorded in baselines; dictionary ordering does not change binding identity.

A failure before commit rolls back the batch. A confirmation failure after acknowledged commit reports `CommittedConfirmationFailed`; a fresh-context/fresh-process rerun resolves the same 171 identities. A commit exception without acknowledgment reports `CommitOutcomeUnknown` and requires reconnect/rerun. Neither path replays a player action. Lost acknowledgment at the actual network boundary is not simulated by the test checkpoint.

## Verification and limits

The dedicated `tests/ArmageddonTraditionNativeHarness` loads actual installed native skills, cap expressions, improver, capabilities, merits and reviewed utilities from uniquely owned disposable MySQL instances. It checks transaction rollback, lost post-commit confirmation with independent-process rerun, stable identities, builder edits/clones, deletion/retirement/competing claims, and unchanged persisted player records. Its native actor attaches actual capability merits and calls the authored enrolment hook. Actual native skill use crosses Unravel 79.5 → 80 and opens Draw Water at 30/grade 1; native skill use obeys cap 90. Unsupported branches stay absent.

The runtime fixture edits only its disposable improver to chance 1 and cooldown 0 for deterministic progression. It runs an explicit Self-only gathering subset, credits 2 reserve, and checks direct Sense casting debits its source cost of 50. Funding that one cast uses an explicitly labeled controlled fixture credit; installation/enrolment do not provide it. The other default method families receive native configuration validation and unit coverage, not a gameplay certificate for all Gentle/Land prices. Existing direct, progression, support, capacity, practice, speech and area checks can run independently through the lane entrypoint on fresh endpoints. The shared harness dispatch is unchanged.

This is controlled native Character/Body/resource/skill/item/database verification, not a full boot, Telnet/login or player/chargen integration certificate. Existing support fixture coverage is not certification of a stock Identify/Component Crafting installer branch. The full 82-spell repertoire, seven elemental traditions, optional class roles, capacity-package selection and enabled interactive workflow remain future integration work. Keep this checkpoint's evidence separate from the central completion ledger.

Run the harness after a Debug build with `Run-IsolatedTraditions.ps1 -Mode traditions -EvidenceRoot <owned-path>`; the other accepted modes are `direct`, `progression`, `support`, `capacity`, `practice`, `speech` and `area`. Each invocation records source/assembly fingerprints and its owned endpoint/datadir/UUID/process evidence, then verifies graceful shutdown and removes only its temporary instance. Historical failed trials remain in the task evidence directory. Final receipts identify the exact source and locally committed checkpoint separately.
