# Environmental Magic Acceptance Mapping

This document maps the revised Task 1 functional and scheduling requirements to the checked-in regression tests. It describes what each test actually asserts. A requirement label or a source mapping is not a passing execution result.

**Execution status, 13 September 2026:** the final repository fast gate passed all 5,547 tests across nine suites, including all mapped environmental regressions. Targeted Debug/Release engine builds passed. Disposable MySQL upgrade and fresh installer import passed; live creation, cloning, attachment, advancement, idempotent damage/repair, flush/restart, inspection and disabling passed. See [verification evidence](Environmental_Magic_Verification.md) and the [108-scenario performance report](Environmental_Magic_Performance.md) for results and their limits.

See the [builder guide](Environmental_Magic_Builder_Guide.md) for commands and input units, and the [runtime contract](Environmental_Magic_Runtime.md) for sampling, persistence and scheduling policy.

## Additional safety and authoring checks

`Coordinator.SynchronousProgExceedingTheSoftBudget_StopsAfterOneCellAndThrottlesProfileLogs` sets the soft budget below one synchronous invocation, then asserts that each pump stops after that complete cell, counts the slow invocations and emits only one throttled profile/prog diagnostic. It verifies cooperative budget handling; it does not claim that synchronous FutureProg execution can be preempted.

`Surface.MagicEnvironment_ActualAdminDispatcherRoutesBindingsInspectionAndRechecks` exercises the real administrative dispatcher. `Surface.MagicEnvironment_PlayerCommandTreesCannotApplyStaffOperations` checks ordinary-player rejection through both command trees and the direct administrative helper. `Surface.MagicEnvironment_DamageAndRepairForwardStableIdentityAndAuditReason` checks caller identity and audit reason forwarding, while `Surface.MagicEnvironment_InvalidStaffRequestDoesNotInvokeOperation` covers non-finite, negative, missing-attribution and malformed-identity input. `Surface.MagicEnvironment_PendingOperationPreventsBindingWithAnActionableError` verifies that a pending durable operation yields a useful error instead of a false binding-success message.

Persistence failure cases also include `Persistence.UnavailableConfirmation_RetainsTheFreezeAndRejectsAnotherOperationIdentity`, `Persistence.OrdinaryDuplicate_PreservesNewerUncommittedResourceChanges`, `Persistence.FailureBeforeCommit_PreservesLiveStateAndDoesNotApplyProjectedProduction` and `Persistence.RolledBackClaim_ConfirmedAbsenceReleasesTheFreezeAndRetainsOlderDeferredWork`. They distinguish an ordinary duplicate from uncertain commitment and confirmed rollback; they do not assert a real database transaction merely from the in-memory store.

`Model.EnvironmentalMigration_PreservesExistingBalancesAndLeavesProfilesUnassigned` verifies additive migration operations with no data replacement. `Model.EnvironmentalState_UsesOnePhysicalCellKeyAndOptimisticConcurrency`, `Model.EnvironmentalBindings_KeepMissingProfileIdentityForDiagnostics` and `Model.OperationReceipt_DuplicateDeliveryCannotTrackTwoRowsForOneIdentity` verify model keys, concurrency, diagnostic identity retention and EF's duplicate tracking rejection. Applying the migration, concurrent database transactions and restarting a real server remain separate execution evidence.
