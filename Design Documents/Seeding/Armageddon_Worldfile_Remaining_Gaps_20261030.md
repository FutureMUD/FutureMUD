### Ranked implementation choices

1. **HP bandaging — recommended next.** `skills.c:248–350` requires the bandage skill and a held tool subtype 5. Ordinary treatment refuses above half maximum HP plus 10, below half maximum HP minus skill, or below -6 HP. Success adds a potency/skill-based HP roll (at least 1); failure removes 1–12 HP and can kill. An attempted eligible treatment consumes the bandage. Potency >=8 and skill >=50 can instead cure magical poison, then generic poison, in that order; unsuccessful cure checks fall through to the remaining logic. Native bind/tend are wound-treatment systems, not this HP action; existing healthcapacity/healthremaining queries, native checks, HP wounds, and family-aware toxin cures provide most pieces. Recommend a held-item command prog using the installed Bandage trait, the source eligibility/consumption/priority rules, native wound-budget healing and native direct harm. Expose a small reusable nonmagical healing action only if needed; do not disguise bandaging as a magical spell or silently add complex-health support. **Luke decides:** approve HP restoration plus potentially lethal failure and poison extraction as the bandage adaptation. **Coordinator decides:** command-hook wiring, native check binding and source range normalization; bring any material difference in numerical thresholds back rather than inventing a model.

2. **Teleport runes — next after bandaging.** `magick.c:14880+` teleports to the rune's current room on the same plane, rather than making the rune itself a use-to-teleport item. `utility.c:4736+` makes it visible to magical detection or its source creator identity. All eight placed definitions lack PC/account creator metadata, so no creator should be fabricated; some numeric value slots contain historical garbage and must not become room IDs. FutureMUD already has live-rune anchors and weighted Waystep travel, but `SpellTravelAnchorResolver.cs:28+` requires legal ownership, and `CastingTriggerTravelDestination.cs` uses that owned-anchor selector. A public world rune cannot safely be represented by assigning an invented owner. Recommend an explicit, optional public/detector-authorised anchor mode with saved native visibility/admission policy, reusing existing destination, same-plane and interdiction checks. Keep existing owned runes unchanged. **Luke decides:** allow these placed creatorless runes to be discovered/targeted through native magical detection as public anchors. **Coordinator decides:** exact source metadata parsing and onload persistence; no new teleport framework or numeric destination guessing.

3. **Charged devices — separate bounded tranche.** Source `other.c:3370+` accepts donated Mana; `3490–3712` selects a spoken power word, checks the stored maximum level and subtracts a grade-dependent reservoir cost. Wands cost 600 + 200*(level-1), lose 100 maximum capacity per non-artifact use, and target a local entity. Staves use 10*mana_amount_level and dispatch their spell without that explicit target. FutureMUD ChargedMagicDevice stores homogeneous frozen spell charges, validates spell effect/target adapters, and normally fills banks through a caster production route. Its compatibility list does not admit every source payload (notably travel/summoning effects). Recommend a fixed-grade native-charge conversion only for a device whose entire spell/target payload is supported; keep incompatible devices explicitly inert until their mapping is agreed. **Luke decides:** fixed-grade charges and native recharge in place of donated variable Mana/capacity erosion, plus treatment of level-8 source data versus native grades. If exact reservoir/power-word behaviour is desired, that is a reusable optional device mode, a larger scope—not a seeder-only data fix. **Coordinator decides:** enumerate exact spell identities, starting charge count and compatible target carrier before enabling each device. Do not silently truncate an unsupported effect or clamp level 8.

Malformed note pages need a concrete repair policy; sealed-note/teaching semantics need actual effective-state evidence. ## Approved negative HP and bandaging continuation

Luke approved optional negative HP thresholds and critical recovery, with the Mul exception supplied by a racial merit whose applicability requires active rage. The agreed native recovery tuning is one real-minute Endurance check: Normal at 0 to -2 HP, Hard at -3 to -10; success restores 1 HP, failure removes 1 HP. Ordinary damage healing is suspended in this range and random progression pauses offline. This deliberately adapts source regeneration probabilities; it does not copy them. Thresholds are 0 for HP unconsciousness, -3 for mortal injury and -11 for death. Existing games remain unchanged unless these strategy options are enabled.

Bandaging uses native checks, signed HP, explicit nonmagical healing/harm and existing toxin families. Its source skill/HP eligibility, held subtype-5 tool, consumption and poison priority remain the implementation contract. Public rune admission and charged-device policies are still outstanding; their earlier decisions are not implied by this approval.

### Implementation status

Negative HP, critical recovery, the racial Mul Rage merit and HP bandaging are now implemented. This supersedes the earlier bandaging-pending rows and recommendation above.
