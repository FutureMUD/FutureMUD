# Armageddon Setting Seeder

The public installer type and menu identity are `ArmageddonSettingSeeder` / **Armageddon Setting**. It is enabled in Debug and Release. Its durable ownership namespace intentionally remains `ArmageddonMagicSeeder`; changing the public name must never orphan existing content or player references. Historical magic receipts retain their original names.

The approved early packages, magic, mundane progression/merits, inactive heritage and source-specific actions are implemented. Current-schema combined classes/subclasses-on installation, gameplay, preserving resume/rerun and first/cold server boots pass. Physical/appearance activation remains gated for owner review. See [the execution ledger](../../Armageddon/Armageddon_Setting_Implementation_20261019.md) for exact evidence and limits.

Use Core -> Time/Attributes -> Skill Package (`skillpreset=Armageddon`, retaining the six canonical legacy answers) -> Human -> Combat (`skilloption=armageddon`, separate Parry, no firearms) -> Chargen (Class/Subclass enabled) -> Setting. Generic Culture, Useful, Health, Animal and Item are not baseline dependencies. Human/Admin/Admin Speech remain shared bootstrap foundations.

The early skills are a new-world alternative. They reject pre-existing player skills rather than converting a world. Canonical traits and cap expressions have stable owned IDs and field baselines; ungranted hidden engine scaffolds supply explicit native consumers. The late Setting phase installs seven guilds and 24 subclasses with source cap expressions; language caps remain 200. No existing player is enrolled or recomputed. Reruns resolve typed ownership and retain builder names, expressions and player values.

Ten first-install static trait IDs bind appraisal, haggling, skinning, writing, Drawing/Tattoo, auxiliary defaults and Pilot. Reruns retain builder configuration. Pilot manual room-exit proficiency is enabled only by the new-world Armageddon choice; its [source/adaptation contract](../../Armageddon/Armageddon_Pilot_Contract_20261019.md) separates recovered behavior from native safety/entitlement changes.

Combat uses the canonical traits, including the exact four approved Two Handed type assignments and independent Parry. Its first install is transactional. Subsequent Armageddon runs validate retained weapon references without running the generic combat refresh over builder changes. The first install gates generic Bash and rebinds manual Bash/Kick to the explicit [physical impact profiles](../../Armageddon/Armageddon_Physical_Impact_Contract_20261019.md). Separate Razor and Trident types, attack rows/message links and melee components bind their own canonical skills and independent Parry, using authored sword/spear geometry. The native armour repair component binds canonical Armor Repair and the shared Core Military Armour tag; supplies500/severity Grievous are authored starter tuning. No donor type assignments are replaced by these adaptations. Its three owned Backstab/Sap profiles use specific proficiencies and distinct command selection. This is preservation, not a promise that every future stock revision reconciles yet.

Setting questions are `install-armageddon-setting` (default No), fixed `armageddon-progression-mode`, capacity/native bindings when needed, plus the retained hidden prepared-world API `install-armageddon-setting-prepared` / `armageddon-setting-prepared-bindings`. The durable fixed settings/shared mirrors remain unchanged. Reflection metadata, replay profiles, tests and native harnesses use the new public type. The normal strict replay inventories still decline Setting by default.

The owned mundane merit definition phase supplies Bard's existing language-only Skill Learning configuration (branching 50, improvement chance 5) and Mercenary's Liver Clearance multiplier 2. Bard and Mercenary receive these merits through their owned subclass links. Clearance multiplies effective liver function after injury for alcohol and every active drug, including beneficial drugs; no needs-rate merit is stacked and no poison damage resistance is granted.

The mundane phase composes 317 effective skill memberships from 226 source main rows, 93 subclass entries and seven writing grants, treating Analyze as a binary role capability and the two source advantages as merits. Native additive role trait rows are deliberately absent. See [role skill progression](../../Characters/Role_Skill_Progression.md) for roots, prerequisites, overlap arithmetic and restart-safe one-time claims. No existing character is enrolled by installation or rerun.

Magic continues to compose its existing independently committed, resumable modules. See [the magic integration guide](../../Magic/Armageddon_Installer_Integration_Guide.md) for their detailed contracts. Existing-world conversion and new scripts remain outside this slice. The later approved naming addition retains free entry and adds personal-only suggestions; see [naming provenance and constraints](../../Armageddon/Armageddon_Naming_Integration_20261020.md).

The nonphysical heritage phase installs five owned language objects and cultures (Allanaki, Labyrinth, Tuluki, Nomadic, Desert Elven), seven ethnicities attached to their exact profile rows, an unavailable common Elf parent, and the approved naming catalogue. The original free-entry naming identity remains for existing references. Fifteen accents comprise the five recovered regional identities plus clearly authored neutral/learner scaffolds. Generated progs preserve the configured free-skill delegate and apply the approved native200/secondary100/60 claims by maximum with role openings. Nomadic background approval defaults false until an explicit compatible policy is bound. No city spawns or scripts are added.

All eight new Race rows default unavailable. They copy complete mapped Human scalar scaffolding, including public height/weight fields, without adding inherited natural attacks a second time. They are not approved physical or appearance profiles. The original scaffold baseline stays fixed across reruns; later bootstrap edits do not become new racial stock defaults. Deliberate row/reference overrides and removed naming links are retained and reported. The [revised physical proposal](../../Armageddon/Armageddon_Physical_Proposal_20261019.md) records the remaining acceptance gate and unit audit.

Approved racial physiology now uses [intrinsic racial merits](../../Characters/Intrinsic_Racial_Merits.md): environmental thirst for all seven profiles (a separate Desert Elf adaptation), stamina+60 for Desert Elf/+20 for Half-Giant and Mul, and Giant hunger3/thirst3/alcohol1 paired with48/24 satiation capacity. Race rates stay1 to avoid double multiplication. The common Elf parent grants no environmental merit. Definitions, links and contextual numeric progs preserve builder edits/removals on rerun. This adds no automatic profile availability; remaining physical/lifecycle activation work is separate. Native Highsun and a source-condition-to-litres conversion are unavailable, so the documented stock hydration adaptation changes passive thirst counters and retains a zero water-loss prog.

Canonical check bindings distinguish Flee from Ride-based mount control/fall avoidance and connect Hunt, Rescue and Charge. Owned expression and reference fields preserve builder overrides through the early package handoff. Disarm auxiliaries use Disarm against Parry only for disarming; other effects retain their explicit scaffold defenses. Optional Trap installation reuses canonical Trap and rejects unowned check collisions rather than overwriting custom formulas. It remains optional.

After every required early check resolves, the explicit fresh-world Armageddon choice enables Pilot, Direction Sense, hostile Guarding and Haggling. Reruns retain later builder opt-outs. These flags do not grant skills. See [Backstab attacks](../../Combat/Backstab_Attacks.md) for specific proficiency and callback revalidation.

Fresh installs disable unallocated Electrical/Programming commands; subsequent builder choices survive reruns. Native boot's generic optional Trap check backfills remain explicitly unbound and do not qualify the optional adapter. Owned creature float speeds retain their original identities after native boot adds a compatibility speed to shared source anatomy; deliberate overrides and unrelated collision checks remain intact.
