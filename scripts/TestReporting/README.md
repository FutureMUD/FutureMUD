# Test-reporting execution guarantees

Use the paired repository test scripts as described in the [test execution reference](../../.codex/references/test-execution.md). The reporter retains native logs and structured TRX evidence; missing or contradictory evidence never counts as a pass.

Each worktree has one cooperative owner. The reporter holds `.artifacts/test-runs/.worktree.lock` with `FileShare.None` for the entire run and keeps the current run identifier in the readable `.worktree.lock.owner` sidecar. A contender reports `BLOCKED` without building or testing. The marker is diagnostic only: a stale marker does not block a run after the operating system releases the lock. Other tools and editors do not participate in this lock.

Windows redirected process streams use synchronous pipe handles in [.NET 10](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Diagnostics.Process/src/System/Diagnostics/Process.Windows.cs). Each stdout/stderr copy therefore gets a dedicated reader thread so parallel test hosts do not consume the thread-pool workers needed for exit and deadline continuations. Other platforms retain asynchronous copies. Log capture remains bounded after process exit; an incomplete drain is still reported as incomplete evidence.

Git evidence uses the same dedicated-reader principle on Windows and concurrent asynchronous readers on POSIX. Both streams are consumed from process start; stdout retains the existing text decoding and all characters for hashing, including NUL separators and tails without a newline. Stderr retains only a 4,096-character diagnostic prefix while continuing to consume warnings through EOF. A successful command with warnings remains valid; a nonzero exit rejects all stdout and reports bounded, sanitized operation/exit context.

Every Git operation has an internal 60-second ceiling linked to the original run deadline, including Human mode without an overall timeout. The deadline also covers initial HEAD, both source captures and cancellable file hashing. Each completed Git process has at most five seconds to finish its readers, within that operation ceiling. Cancellation, incomplete drains and exceptions attempt termination of that invocation's owned process tree and use at most ten seconds for parent reaping, reader cleanup and pipe closing. Cleanup uncertainty retains the original reason; parent exit alone does not establish descendant termination. The worktree lock remains held through this cleanup.

Missing Git before source capture is `PREREQUISITE_UNAVAILABLE`/BLOCKED. Failed or timed-out initial capture prevents build/test execution and another fingerprint attempt. Expired runs do not launch end capture. Missing end evidence leaves stability unknown and reports `SOURCE_CHANGED` plus the appropriate timeout/prerequisite/reporting issue. Only two completed fingerprints can establish stable source; confirmed build/test failures retain precedence.

The reporter suite exercises eight simultaneous hosts, both complete 200 KB output streams, interprocess ownership and release, contradictory exits, missing/stale/malformed reports, source changes and deliberate timeouts. Healthy fake-runner scenarios have a 30-second budget for loaded CI machines; the intentional timeout scenario retains its three-second limit.

The compiled FakeGit fixture additionally covers stderr-first, stdout-first and alternating 2 MiB streams, exact NUL/newline/tail preservation, nonzero exits and secret/control sanitization, missing executables, operation/caller cancellation, pre-cancelled launch prevention, owned descendants, inherited open pipes, initial/end fingerprint deadlines and real-Git hash compatibility. An explicit readiness marker precedes cancellation. A bounded test reproduces the old serial-reader deadlock; fixture cleanup terminates only recorded owned PIDs. Reporter child processes run with `DOTNET_PROCESSOR_COUNT=2` and drain both receipt streams concurrently. Test-only executable overrides are scoped to each child process environment.
