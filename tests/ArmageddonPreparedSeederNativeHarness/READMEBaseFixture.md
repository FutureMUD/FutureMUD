# Reusable pre-Armageddon seeded base

This harness can capture one reusable seeded world **before invoking ArmageddonSettingSeeder**. The full Debug replay inventory remains strict: `RunPrefixBefore` validates every enabled step and question, then executes only the nonempty prefix. Ordinary `Run` still refuses truncated profiles and previously seeded databases. The maintained `medieval-standard` prefix ends with SupernaturalSeeder; its exact step types and answer inventory are stored in the descriptor. It has the profile's Chargen class choice (`no`).

Build the dedicated harness from the current source, then use its existing owned-instance wrapper:

```powershell
.\Run-IsolatedPreparedSeeder.ps1 -Mode base-fixture-capture
.\Run-IsolatedPreparedSeeder.ps1 -Mode base-fixture-restore -BaseFixture <captured-base-world.json> -BaseFixtureSha256 <capture-descriptor-SHA256>
.\Run-IsolatedPreparedSeeder.ps1 -Mode base-fixture-package -BaseFixture <captured-base-world.json> -BaseFixtureSha256 <capture-descriptor-SHA256> -PackageMode Classic
# For an S4 installed-stock first/cold qualification, use the explicit scope:
.\Run-IsolatedPreparedSeeder.ps1 -Mode base-fixture-package -QualificationScope s4-stock -BaseFixture <captured-base-world.json> -BaseFixtureSha256 <capture-descriptor-SHA256> -PackageMode Classic
```

Capture writes a unique directory beneath this worktree's `.artifacts/pre-armageddon-base-fixtures`. Its canonical SQL and `base-world.json` are sealed read-only and preserved. Capture does not claim a verified dump round trip; the first successful **clean restore** supplies that evidence. Each restore creates a new randomly named owned disposable database, imports a temporary rewritten SQL copy with `DatabaseUpgradeCoordinator.ImportBlankDatabaseSnapshot`, replaces the imported ownership marker with the new target's marker, and disposes only that target. The original SQL is never rewritten. No existing world is selected or reset.

The descriptor pins kind/version, original owned database, sibling SQL filename/hash, exact profile prefix/answers, actual ordered migration history, live column/index/key/foreign-key schema hash, base content hash excluding only the necessarily resealed ownership row, base source inventory/hash, and blank snapshot/manifest hashes. Restore requires an explicit descriptor hash, rejects directory/file reparse points and escaping paths, checks SQL database targets, and verifies no pending migrations/model drift or Armageddon package claims/settings/answers. Post-S3 catalogue dumps are not compatible bases.

Base fingerprints include base seeder code/shared workflow/resources and database/model/migration inputs. `DebugSeederReplay.cs#runner` hashes execution code separately from profiles; prefix answers are pinned independently. Armageddon seeder content, `FutureMUDLibrary/Magic/Stock` and explicitly identified S4-only owned-creation configuration/anchor/service/mission/presentation contracts are excluded. General shared types remain fingerprinted. Harness execution/source evidence is recorded separately from base-data compatibility. S4-only edits there do not invalidate the base. Relevant base/schema changes require an explicit new capture; original dumps are preserved. A compatible existing descriptor refuses repeated capture. `-FreshInstallCheck` explicitly allows an additional fresh-install verification when requested.

Targeted package mode uses the ordinary shared executor, current question filters/validators, explicit Classic/Simple selection, and the unique base Willpower capacity attribute. It executes Armageddon once, never replays foundational seeders. Optional later steps are omitted unless passed explicitly as `-LaterSteps PsionicsSeeder,EnvironmentalExposureSeeder`; only those two exact later steps are admitted in profile order. **An S4 qualification must use `-QualificationScope s4-stock`.** The wrapper checks the exact parent-directory boot-script copy before starting MySQL, sets the stock-smoke flag and fresh boot output itself, then requires a passing paid campaign and equal nonzero first/cold installed-definition counts. The plain package mode is catalogue scope and cannot be reported as S4 stock qualification. Existing explicitly configured boot tooling remains available through `FUTUREMUD_PREPARED_REPLAY_BOOT_SCRIPT` for other lanes.

The wrapper saves source/assembly evidence, owned-instance metadata, and `base-world-run.json`. Capture receipt has `CAPTURED`, descriptor/SQL/base-source hashes, prefix boundary/count and latest migration; restore has `RESTORED_CLEAN` or `RESTORED_AND_TARGETED_PACKAGE`, hashes, fresh ownership, exact executed step list, `FullReplayExecuted=false`, immutable SQL and verified dump round trip. Package receipts additionally record selected mode/later steps and current package content source hash. Success certifies only the executed lane; missing boot configuration supplies no gameplay certificate.

Direct harness environment equivalents are `FUTUREMUD_BASE_WORLD_FIXTURE`, `FUTUREMUD_BASE_WORLD_FIXTURE_SHA256`, `FUTUREMUD_BASE_PACKAGE_MODE`, `FUTUREMUD_BASE_LATER_STEPS`, `FUTUREMUD_BASE_WORLD_RECEIPT`, and `FUTUREMUD_BASE_FRESH_INSTALL_CHECK`. Prefer the owned wrapper. The pure `--base-fixture-check-run` entrypoint opens no database and exercises descriptor digest/kind/boundary/sibling/ownership/source/answer/migration/dump-target refusal scenarios. Durable prefix execution/refusal regressions live in `DatabaseSeeder Unit Tests/SeederReplayTests.cs`.

This workflow implements the current [S4 direct/shared/sampled qualification strategy](../../Design%20Documents/Magic/Armageddon_S4_Qualification_Strategy_20261013.md). Reuse the canonical base and installed fixtures where isolation is reliable; run focused new-behaviour checks and consolidated milestone acceptance. Preserve original assertions and failures. A repeated base replay after S4-only content edits is not the default.

## Separate S6 measurement scopes

The later source-gathering checkpoint authors the retained Sorcerer Self/Land, Preserver Self and Defiler Land policies behind false availability gates. The preceding historical matrix statement about unauthored gathering describes its original receipt, not the current package.

The explicit `-S6MeasurementScope ui-funding|progression-faults|borrow-retirement` lanes are separate representative measurements. They do not execute/reuse N24 or wait for ash expiry. The original readiness maintenance guard is unchanged.

```powershell
.\Run-IsolatedPreparedSeeder.ps1 -Mode base-fixture-package -QualificationScope s4-stock -S6IntegrationSmokeOnly -PackageMode Simple -EarlierClasses On -BaseFixture <base-world.json> -BaseFixtureSha256 <pin> -S6MeasurementScope ui-funding -ReadinessCommands <explicit-ui-files.json> -EvidenceRoot <fresh-owned-evidence-root>

.\Run-IsolatedPreparedSeeder.ps1 -Mode base-fixture-package -QualificationScope s4-stock -S6IntegrationSmokeOnly -PackageMode Simple -EarlierClasses On -BaseFixture <base-world.json> -BaseFixtureSha256 <pin> -S6MeasurementScope borrow-retirement -EvidenceRoot <fresh-owned-evidence-root>
```

The UI file maps `sorcerer` and `earth` to explicit ordinary chargen answer files. Only UI funding accepts this argument. Progression faults use explicitly controlled positive native gain/mastery on private copies; canonical definitions and prices remain unchanged. Borrow retirement targets the accepted canonical `possesscorpse` adapter, an exact secondary `CharacterInstances` DELETE and the original corpse/body/foreign item. It does not substitute the corpse-animation lifecycle journal. `AWAITING_COLD` is intermediate; overall PASS requires actual cold conservation and repeat-idempotent recovery. The 18 October measurement exposes a production exception terminating the server at this boundary; recovery remains unqualified. See [the targeted measurement report](../../Design%20Documents/Magic/Armageddon_S6_Targeted_Measurements_20261018.md).

Freeze tested inputs, use one operator per owned database, stop at the first assertion/protocol/ownership failure and preserve every FAIL/NOT_RUN. Fixed overall operator budgets are65/45/30 minutes respectively; driver/parent limits are separately bounded. Run receipts pin source/build/base inputs and exact first/cold assertions. No lane enables original stock/Class or Release availability, merges or deploys.


## v1 original-stock Release acceptance

The explicit `-ReleaseStockSmokeOnly` lane supersedes the historical statement above that no lane accepts enabled Release stock. It cannot be combined with S4/S5/S6/fault switches. Build this harness in Debug (fixture owner) and Release (actual installer); the Release build also supplies the actual Release server. Copy `PreparedCatalogueBootSmoke.py` to the worktree parent only after checking its source hash. Capture a **current** classes-on base once when historical fixtures fail source compatibility; do not rewrite an old descriptor or widen compatibility rules to force reuse.

```powershell
.\Run-IsolatedPreparedSeeder.ps1 -Mode base-fixture-capture -EarlierClasses On -EvidenceRoot <new-capture-root>
.\Run-IsolatedPreparedSeeder.ps1 -Mode base-fixture-package -ReleaseStockSmokeOnly -EarlierClasses On -PackageMode Simple -BaseFixture <current-base-world.json> -BaseFixtureSha256 <exact-capture-digest> -EvidenceRoot <new-release-root>
```

The Debug parent validates the immutable descriptor, source/answer inventory, schema/content/migrations and clean restore using the existing procedures. It delegates only the restored owned database to a Release child, retaining sole disposal ownership. The Release child runs the real shared seeder executor and audits original complete casting/Class and independent gathering/device gates. It copies a mundane body into an ordinary Player account, attaches the original permanent Earth merit, and supplies no magic skills, knowledge or energy. The first/cold Release server uses that original policy for explicit native enrolment, empty-reserve refusal, actual minute rest funding, full-price timed canonical practice and conserved cold state. There are no private enabled capabilities, changed generator/improver values or fault injections. Full UI/approval evidence remains in the dated qualification; this is one representative packaging smoke, not a repeated matrix.

The scenario has a fixed 900-second funding limit and 1,140-second Python budget. The Release child has a 32-minute outer install/boot allowance: measured installation took about 8.5 minutes before the separately bounded 20-minute boot handoff begins. Receipt `release_stock_boot_receipt` records Release server assembly hashes and separate copied-body limitations; source manifests and exact installation logs distinguish Debug fixture ownership from Release execution. Original stock XML is checked on both boots. Overall PASS requires native first/cold payment/progression assertions, stable inputs, stopped MUD trees, database disposal and verified isolated MySQL/datadir cleanup. A failure stops dependent steps and remains recorded.

The regional follow-up adds `-ReleaseRegionalSmokeOnly` alongside `-ReleaseStockSmokeOnly` in that same isolated package lane. It selects a distinct original Sorcerer/wildland scenario and `regional_land` first/cold receipt, preserving the dated Earth results. Capture a new compatible foundation after the regional schema change; historical descriptors remain immutable. Two physical fertile rooms in one new Area begin with six shared life through the normal builder binding, pay six regional actions, refuse a route with no matching local source, then pay the approved native room-forage fallback. Original profiles/capabilities/spells are pinned; pool, receipts, mana, forage, scars and participant keys must conserve across cold boot. The literal no-room-profile route is a separate managed runtime test. No hour/ash wait, balance matrix or exceptional failure campaign is included.
