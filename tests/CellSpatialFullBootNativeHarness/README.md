# Cell spatial full normal-boot acceptance

This Windows-only native acceptance host is for an explicitly authorized disposable rehearsal. It creates its own fresh loopback MySQL instance and uniquely named owned database. Do not substitute an existing world connection. It requires MySQL binaries, .NET 10, the repository's pinned packages, a private historical source archive and Debug-built helper assemblies.

The historical fixture is source commit `ba05f5309af9d304fe91b5d5eb821ffea6651578`: Cell identifiers exist and Rooms still own zone/XYZ. Build its unchanged `DatabaseSeeder` and `MudSharpCore`. Build `HistoricalSeeder` with `BaselineRoot` pointing to that private archive; build `StartupHook` against the archive with `Legacy=true`; build `StartupHook` again against the current checkout with `Legacy=false`; then build `CellSpatialFullBootNativeHarness.csproj`. Use serial `-m:1` builds and the repository's restore/verification guidance. The stock replay helpers require Debug builds.

The operator sets process-local `FUTUREMUD_CELL_FULLBOOT_BASELINE`, `FUTUREMUD_CELL_FULLBOOT_SEEDER`, `FUTUREMUD_CELL_FULLBOOT_LEGACY_HOOK` and a new `FUTUREMUD_CELL_FULLBOOT_OUTPUT` directory under the task's `fullboot-qualification` directory. The native coordinator requires the sibling historical archive to be named `fullboot-baseline`. Set process-local TEMP/TMP to a short owned workspace directory, preserving and restoring their exact previous values. Windows MySQL table-file paths can exceed limits under deeply nested defaults. Run `Run-IsolatedFullBoot.ps1` from the current checkout. Its private connection descriptors, server UUID/port/datadir, ownership marker and parent job attachment are mandatory admission checks, not user-supplied world selection.

With `FUTUREMUD_CELL_FULLBOOT_WARD_PROBE=1`, the run stops after a genuine historical preparation and second normal historical boot; no spatial migration occurs. This isolates the historical persisted ward-reference binding defect. Keep its failure receipt and cleanup evidence. With the flag absent, a separate fresh world runs the structural scenario, including a complete schema/row/DDL/history backup restore and matching private-file/historical-binary restore with another historical normal boot.

Every normal server child launches the real production `MudSharp.dll` entrypoint with its owned connection. The test-only [official .NET startup-hook contract](https://github.com/dotnet/runtime/blob/main/docs/design/features/host-startup-hook.md) installs a console observer before `Main`. Only after the actual final cell-loading and readiness messages does it enqueue the scenario on the real main game thread. The server still performs its normal initialization, game loop and graceful shutdown. No production loader or entrypoint is replaced.

The structural scenario covers unequal Room/Cell IDs, duplicate XYZ, overlapping Areas, explicit and fallback defaults, native NPC/body/primary-instance identities, loose/held/contained custody, hosted interiors and docking, nonregenerating cell magic balances and foraging yield. After migration it exercises occupied rezone, create/clone/identifier/save/Area changes, loaded-content deletion and real temporal-listener cancellation, occupied vehicle retirement refusal followed by evacuation and retirement, and valid persisted dwelling parent deletion. A normal cold boot checks exact surviving identity/ownership/custody and absence of entity replay. The valid persisted dwelling avoids the separate preexisting dwelling-generator defect.

Each child has a ten-minute deadline. Failed prerequisites stop dependent phases; owned jobs stop before database disposal. Preserve all failed logs and receipts. Capture source and complete consumed-output manifests before/after execution, accounting explicitly for generated runtime configuration files. This host is additional normal-entrypoint/lifecycle evidence.
